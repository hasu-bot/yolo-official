## 動かす

Node.js 22以上。通常の生成・ローカル表示には追加パッケージは不要。

```sh
npm run build:talents
npm run build
npm test
npm run dev
```

http://127.0.0.1:4173/talents/ を開く。ポートは `PORT=4175 npm run dev` などで変更できる。
サーバーは127.0.0.1にだけバインドする。公開URLや外部アクセス権は作らない。

架空サンプルで一覧・個別ページ・絞り込みを確認する場合：

```sh
PORT=4174 npm run dev:demo
```

http://127.0.0.1:4174/talents/ と `/talents/sample-a/` など。
サンプルはOSの一時フォルダに生成し、リポジトリの `talents/` を上書きしない。
ページ冒頭に開発用・架空の表示とnoindexを付ける。参考コンセプト画像が正規取得済みなら、
その架空人物をCSSで表示範囲を限定して使用する（元のPNGは改変しない）。画像とサンプルは
一時フォルダにだけ置き、公開用assetsやtalentsへコピーしない。参考画像がなければ抽象スウォッチへ戻す。
実在モデル、認定、実績、掲載同意の事実を示すものではない。
通常の生成CLIにサンプルを有効にするオプションはない。

## URLと動線

- `/talents/`：公式モデル一覧、ファッション／ビューティー／ライフスタイルの分類、相談、応募。
  出演内容（写真・映像・広告・イベント）の追加絞り込みは折りたたんで保持する。
- `/talents/<slug>/`：活動名、紹介文、対応内容、活動エリア、任意の身長・特技・ギャラリー・実績。
- ジャンルは `?category=fashion|beauty|lifestyle`、出演内容は `?work=photo|film|ad|event`。併用可能。戻る・進む、詳細から戻る、再読み込みでも維持する。
- 未生成のプロフィールは404。未公開の人の存在や状態を案内しない。
- 応募は既存 `/model/`。既存フォーム、site.js、DB定義は変更していない。
- 仕事相談は既存 https://yolo-soudan.vercel.app/ へのリンク。相談サイト自体は変更していない。
- 「相談メモをコピー」は希望モデル、企画、日程、場所、予算、媒体、使用期間を含むテンプレート。
  自動送信はしない。コピーが許可されなければ、選択可能なテキスト欄を表示する。
- JavaScriptなしでも全プロフィールと相談・応募リンクが使える。絞り込みとコピーのみ拡張機能。

## 掲載条件とデータ管理

現在の `content/talents.json` は空配列。実データ・応募者データは取得も流用もしていない。
HUB職種「モデル」から自動で公式認定へ昇格させる処理はない。DB接続・認定操作・同意代行もない。

新規掲載は、運営による公式モデルの承認と本人の掲載同意が揃ってから行う。
同意原本・審査記録・連絡先・本名・生年月日・NG事項はこのリポジトリへ入れず、運営の非公開管理で保持する。
公開内容（写真、本文、身長、特技、実績など）は本人が確認した範囲だけを登録する。
未成年の場合は保護者の掲載同意記録も確認する。応募時の同意と掲載同意は別。

レコード構造は `publication` と `profile` の2つ。

`publication` の必須項目：

- `status: "approved"`（公式モデルとして承認済み）
- `consent: "granted"`（掲載同意取得済み）
- `consentVersion`、`consentRecordedAt`（YYYY-MM-DD）
- `profileConfirmed: true`、`photosConfirmed: true`（公開する内容と写真を本人確認済み）
- `isMinor: true|false`。trueなら `guardianConsentRecordedAt`（YYYY-MM-DD）も必須

`profile` の項目：

- 必須：`slug`、`name`（活動名）、`romanName`、`intro`、`area`
- 任意：`height`（整数cm）
- 任意：`categories`（`fashion`、`beauty`、`lifestyle`の配列。対応するイメージ・ジャンルのみ）
- `works`：`photo`、`film`、`ad`、`event`のうち対応できる内容の配列
- `portrait: {src, alt}`、`gallery: [{src, alt}]`
- `skills: []`、`credits: []`（どちらも空配列可）

写真は同意取得済みの実写だけを `/assets/talents/<slug>.jpg|jpeg|png|webp` に配置する。
写真パスはローカルの限定パスのみ。生成画像や応募時の私的な写真を本番用として使わない。
`publication` が不完全ならプロフィールを生成しない。承認・同意フラグが揃っていても、
証跡の日付・版、未成年同意、許可外の公開フィールド、重複・危険なslug、画像ファイル不在などは生成エラーになる。
出力は明示的な公開フィールドだけで、審査・同意の管理情報をHTMLやJSへシリアライズしない。

公開対象の変更後は `npm run build:talents` とテストを実行し、生成された `talents/` も差分に含める。
`talents/` は毎回再生成し、取り下げた人の古いHTMLを消す。
掲載終了時は使わなくなった公開写真も別途削除して差分を確認する。
写真とHTMLの変更は必ず同時にレビューする。掲載判断を生成スクリプトに代行させない。
`npm run build` は公開対象を検証して `dist/talents/` を毎回再生成する。Vercelもこのビルドを実行し、`dist/` だけを配信する。既存トップ・活動記録・応募ページ・公開アセットも含める。
同意の管理情報、ソース、テスト、DB定義、ドキュメント、開発サンプルは出力しない。
`.vercelignore` はCLIのアップロード除外用で、ビルドに必要な `content/` と `scripts/` は残す。これを応募者データの保護手段として頼らない。
