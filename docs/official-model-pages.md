# YOLO TALENTS

公式サイトの白い下地・共通トークンを保ち、参考画像v2の大きな写真4列（モバイル2列）を採用する。人物写真は公開同意済みの実写のみ。架空人物はローカルの隔離デモ専用で、本番ビルドへ入らない。

## 文言と情報の順序（2026-10-18見直し）

比較した実サイトと変更理由は [文言・構成レビュー](./talents-content-review.md)。一覧は「モデル紹介→出演相談→YOLOの紹介・応募」とし、詳しい依頼条件は依頼フォームの折りたたみに集約。カードは活動名・活動エリアを読み取りやすくし、個別から希望モデルを引き継いでフォームへ進む。フォームは企画・使用予定・連絡先の3グループで、必須項目・同意文・送信制御は維持する。

## ルートと正本

- `/talents/`：公開モデル一覧。ジャンル・対応内容の絞り込み。
- `/talents/<slug>/`：プロフィール、写真、対応内容、実績、依頼導線。
- `/casting/?model=<slug>`：YOLOへの依頼フォーム。予算・使用媒体・使用期間を含む必須項目、個人情報利用への同意。
- `/model/`：既存のモデル・俳優応募。応募処理は変更しない。
- `/hub/`：既存のHUBへの転送を維持。

掲載の正本は **yolo-members / Supabase**。本番ページは `api/talents-page.js` がHUBの `/api/talents` から毎回取得してHTMLを描画する。`content/talents.json` と静的生成スクリプトは隔離デモ・テスト用。本番の `dist/` にモデルの静的HTML・元データ・テスト・開発画像は入れない。

承認・本文と写真の運営確認・本人の当該版への掲載同意・公開設定ONが揃う場合だけ表示する。未成年は保護者の掲載同意確認も必要。HUBメンバーが公開中かつactiveであり、元の応募もapprovedであることを確認する。
非公開への変更・同意撤回は次のリクエストから一覧・直URL・写真に反映する。HTML/API/写真はブラウザ・CDNともno-store。既に表示・保存された画像や第三者のキャッシュの消去は保証できない。
HUB障害を「公開モデル0名」と見せず503にする。非公開・不存在のプロフィールはいずれも同じ404になる。

## 依頼の受付

`casting.js` は `https://yolo-members.vercel.app/api/casting` に直接送信する。HUB側はCORSで公式サイトのOriginを許可し、入力を再検証して非公開DBへ保存する。直接通信によりHUB側で実際の接続元IPを制限できる。
入力はクライアントとHUBとDBで検証する。必須項目、文字数、メール形式、対象モデルの公開状態を検査する。受付番号による再送の重複排除、接続元3回/10分・メール3回/1時間の制限をDBで行う。実際の出演は企画ごとの合意で決まり、受付時点では確定しない。
成功時に受付番号を表示し送信済みにする。失敗時は入力と受付番号を維持する。JavaScript無効時は送信ボタンを無効にし、既存相談窓口を案内する。HTML自体もPOSTを指定し、個人情報のGET送信を防ぐ。
依頼はHUB運営画面の「公式モデル・依頼」に集約する。モデル本人への転送・メール/Discord通知はこの変更に含めない。

## ローカル確認

Node 22以上。`npm run build`、`npm test`。
`npm run dev` はオフライン用の空状態。`npm run dev:demo` はOS一時フォルダの架空モデル4名を表示し、noindex・開発用表示を付ける。デモの依頼送信は無効。
参考PNGを `../reference/yolo-model-page-concept-v2.png` に置くと、隔離デモに限り画像を使用する。写真がない場合は抽象画像に戻る。

Chrome検証：`PLAYWRIGHT_MODULE=/path/to/playwright npm run test:browser`。
フォームとHUBの未認証API：HUBを127.0.0.1:3000で起動し、同じ設定で `node tests/casting-browser.mjs`。
`EVIDENCE_DIR` でスクリーンショットの出力先を指定する。
フォームの成功・通信失敗はブラウザ内で応答を模擬し、実際の相談は送らない。SQLの権限・保存は別途HUBの開発DBテストで確認する。

## 公開する場合の順序

今回の範囲はPR・公開前確認まで。本番DBへの適用・mainのマージ・本番公開は行っていない。

1. yolo-membersの移行SQLをレビューして本番へ適用。
2. HUBを公開し、`/api/talents`、本人確認、運営画面、CORSと非公開写真の拒否を確認。
3. 本PRの公式サイトを公開し、Vercelの動的ルート・一覧・404・依頼画面・既存応募を確認。
4. 実際のモデル登録は承認済み応募と本人を確認して行う。実写の掲載許可を取り、HUBから本人が内容を確認し掲載に同意して初めて公開する。

公式側の既定HUBは `https://yolo-members.vercel.app`。別のHUBプレビューを使う場合はサーバー用 `TALENTS_HUB_ORIGIN` を設定する。フォームは通常のHUB本番を指すため、プレビュー上で実依頼を送らない。プレビューの同意済みデータや保護設定を、確認なしで本番へ移さない。
